# NOVRA Intelligence — frontend

The presentation layer, moved off WordPress.com.

WordPress remains the CMS. It stopped being the renderer because the site runs
on WordPress.com Free, where Custom CSS is plan-gated: every rule had to be
flattened into inline style attributes and then survive the platform sanitiser,
which removed media queries, breakpoint-specific composition, hover and focus
states, layered backgrounds and art direction from the design before it ever
reached a visitor.

    WordPress.com  ->  REST  ->  content adapter  ->  Next.js  ->  Vercel

## Layout

    app/         routes, one per public URL, trailing slashes preserved
    components/  UI, each with its own CSS module
    components/graphics/  the inline-SVG graphic environments
    lib/cms/     the single typed data layer
    content/     the committed CMS snapshot and media map
    scripts/     snapshot builder and browser QA

## Content

`lib/cms` prefers a live fetch from the WordPress REST API and falls back to
`content/cms-snapshot.json`, which is the same content taken from the same CMS
with presentation stripped. There is deliberately no second copy of any article:
the snapshot is generated by `scripts/build-snapshot.mjs` from the exact payloads
that were published to WordPress.

    node scripts/build-snapshot.mjs    regenerate the snapshot
    npm run build                      production build
    npm run lint && npm run typecheck  static checks
    node scripts/browser-qa.mjs        real browser QA at 390/620/1024/1600

## URL parity

Every public path the WordPress site serves is served here, including the five
dated article permalinks. `trailingSlash` is on for the same reason. The browser
QA fails if any of them stops resolving.
